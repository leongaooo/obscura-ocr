# 敏感字段模型

## 字段候选结构

每个候选至少包含：

```text
SensitiveCandidate {
  id
  type
  category
  pageId
  bbox[]
  confidence
  evidence[]
  source { rule?, model?, layout?, manual? }
  severity
  recommendedAction
  status
}
```

完整原文应保存在受控数据边界中；普通日志和审计列表只保存字段类型、坐标、哈希和处理状态。

## 分类

- 身份与联系：姓名、电话、邮箱、地址、身份证号码
- 企业与税务：公司名称、统一社会信用代码、税号、客户编号
- 金融与票据：银行卡号、银行账号、发票代码、发票号码、金额和税额
- 凭证与安全：印章、签名、二维码、密钥样式字符串、访问令牌
- 文档隐含信息：作者、批注、修订、隐藏文字、嵌入对象和外部链接

## 严重级别

| 级别 | 示例 | 默认处理 |
| --- | --- | --- |
| critical | 密钥、访问令牌、身份证号、完整银行卡号 | 高优先级不可逆脱敏并强制校验 |
| high | 税号、银行账号、发票号码、手机号 | 默认脱敏，低置信度转人工 |
| medium | 公司地址、项目编号、联系人姓名 | 根据输出用途选择 |
| low | 普通备注、非敏感说明 | 默认保留，除非规则包标记 |

候选状态包括 `detected`、`planned`、`confirmed`、`redacted`、`rejected` 和 `needs_review`。规则包必须声明语言、材料类型、字段类型、版本、来源、许可证、已知误报和评测范围。
